The Quantum Approximate Optimization Algorithm (QAOA) is a hybrid variational algorithm designed primarily for optimization problems. It is especially well known for combinatorial tasks such as Max-Cut.[^ibm-qaoa][^ibm-vqa]

## Conceptual idea

QAOA begins with a cost Hamiltonian $H_C$ encoding the optimization problem and a mixer Hamiltonian $H_M$ that promotes exploration of candidate solutions. The algorithm alternates between evolutions generated by these two Hamiltonians:

$$
\lvert \psi(\boldsymbol{\gamma}, \boldsymbol{\beta}) \rangle
=
\prod_{k=1}^{p}
e^{-i\beta_k H_M}
e^{-i\gamma_k H_C}
\lvert + \rangle^{\otimes n}.
$$

Here:

1. $p$ is the number of layers.
2. $\gamma_k$ and $\beta_k$ are variational parameters.
3. $\lvert + \rangle^{\otimes n}$ is the standard initial state for the usual mixer choice.

The parameters are then optimized classically.

## The Max-Cut example

IBM's utility-scale QAOA lesson uses Max-Cut as the teaching example.[^ibm-qaoa] The procedure is:

1. Start with a graph.
2. Rewrite the objective as a binary optimization problem.
3. Reformulate it in QUBO language.
4. Convert the QUBO problem into an Ising-style cost Hamiltonian.
5. Build the alternating-layer QAOA circuit.
6. Optimize the circuit parameters and sample candidate solutions.[^ibm-qaoa]

This is a particularly instructive case because the full mapping pipeline is visible.

## Why QAOA is associated with NISQ

IBM's variational algorithms lesson explains the main reason clearly: deep circuits are difficult to trust on noisy devices, so QAOA uses relatively short, parameterized circuits inside a hybrid loop.[^ibm-vqa]

QAOA is therefore attractive because:

1. It is variational, so depth can be limited.
2. It maps naturally to cost-Hamiltonian language.
3. It can exploit error mitigation and suppression techniques at utility scale.[^ibm-vqa]

## The adiabatic connection

IBM's utility-scale QAOA lesson presents QAOA as a discrete, trotterized analogue of adiabatic quantum optimization.[^ibm-qaoa] This is an important conceptual point.

Very informally:

1. Adiabatic algorithms change a Hamiltonian continuously and slowly.
2. QAOA replaces that continuous evolution with a finite number of alternating layers.
3. As the number of layers increases, the procedure can more closely resemble the adiabatic limit.[^ibm-qaoa]

This connection helps explain why QAOA alternates cost and mixer evolutions instead of using an arbitrary parameterized ansatz.

## The role of the mixer

The mixer Hamiltonian is typically chosen as

$$
H_M = \sum_i X_i,
$$

whose ground state is the uniform superposition over computational basis states.[^ibm-qaoa]

Pedagogically, the mixer serves two purposes:

1. It provides a simple initial state.
2. It drives transitions among candidate computational-basis solutions.

Custom mixers are possible, but the standard choice is the most common introduction.

## Strengths and limitations

QAOA is attractive, but it is not a universal solution to optimization.

Strengths:

1. The structure is physically interpretable.
2. The circuits can be kept relatively shallow.
3. The algorithm aligns naturally with Hamiltonian encodings of combinatorial objectives.

Limitations:

1. Good performance may require many layers.
2. Parameter optimization can become difficult.
3. Hardware noise may obscure the cost landscape.
4. Logical graph connectivity may require additional routing gates.

These limitations are especially important in NISQ settings.

## Takeaway

QAOA is best understood as a structured variational algorithm for optimization: it encodes the objective in a Hamiltonian, alternates cost and mixer evolutions, and lets a classical optimizer tune the layer parameters so that measured bitstrings are biased toward good solutions.
